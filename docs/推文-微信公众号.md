# OESP 刷飞牛，风扇终于听话了 —— oesp-fanctl 适配版发布

> 从「装不上」到「装上就能用」，我们把 1.6 原版从头到尾改了一遍。

---

## 一、先说痛点

OES Plus（大家常说的 OESP）刷了飞牛 fnOS 之后，风扇这事儿一直是个心结：

- 系统更新一次，风扇不转了
- 好不容易让风扇转起来，它又不听使唤
- 明明 45℃ 该开风扇，它就是不动
- 后台服务一大堆，互相抢控制权

如果你也踩过这些坑，这篇就是写给你的。

这次我把社区里的 `oesp-fanctl`（1.6 版）针对 OESP 的硬件特性做了彻底适配，**安装即用，不用改一行配置**。

---

## 二、根因：原版为什么在 OESP 上不灵

### 坑 1：控制通路被内核「劫持」了

1.6 原版通过这个节点控制风扇：

```
/sys/devices/platform/gpio-fan/hwmon/hwmonX/fan1_target
```

这个节点由内核 `gpio_fan.ko` 驱动提供。而这个驱动加载后，会把自己注册成一个 **thermal cooling_device（散热冷却设备）**。

于是内核的热调控器（step_wise）接管了它 —— **只要 CPU 温度低于 60℃，内核会在约 1 秒内把你刚写进去的值覆盖回 0**。

原版的对策是「每 2 秒重写一次」，脚本注释里写得很直白：

> `# 每周期重写（对抗 gpio-fan 驱动 ~2.5s 自检重置）`

实测结论：**打不过**。写入后约 1 秒就被内核按回去，45℃ 该开风扇的时候，风扇根本起不来。

### 坑 2：压根装不上

原版的安装钩子里有一道硬性检查：

```bash
for f in /sys/devices/platform/gpio-fan/hwmon/hwmon*/fan1_target; do
    [ -e "$f" ] && { FAN_FOUND=1; break; }
done
if [ "$FAN_FOUND" -eq 0 ]; then
    exit 1     # 直接判定安装失败
fi
```

问题在于，OESP 上的 `gpio_fan.ko` **默认不加载**（系统里没有对应的 modules-load 配置）。所以全新系统上根本没有这个节点 —— **应用连装都装不上**。

### 坑 3：和已有风扇服务互相打架

原版安装时只停了 `pwm-fancontrol` 和 `fan-fullspeed` 两个服务，**没停 `fanctl.service`**。如果你之前自己写过风扇脚本，两个程序会同时抢同一根 GPIO，谁也别想控制好。

## 三、核心改造清单

| 维度      | 1.6 原版                 | 适配版（本版）                                |
| ------- | ---------------------- | -------------------------------------- |
| 控制通路    | 写 hwmon `fan1_target`  | **卸载 gpio-fan 驱动，用 `gpioset` 直控 GPIO** |
| 是否受内核覆盖 | 会（<60℃ 被 step_wise 按回） | **完全不受影响**                             |
| 引脚来源    | 依赖驱动自动探测               | **从设备树自动读取，兜底 45**                     |
| 冲突服务    | 只停 2 个                 | **追加接管 `fanctl.service`**              |
| 卸载恢复    | 只重启 pwm-fancontrol     | **新增 `restore`：还原厂商 60℃ 内核温控**         |

### 改造 1：控制通路换成 GPIO 直控（关键）

不再写内核节点，而是：

```
1. modprobe -r gpio_fan        ← 先卸载内核驱动，把 GPIO 释放出来
2. gpioset -m signal gpiochip0 45=0|1   ← 直接控制引脚电平
```

`-m signal` 让 `gpioset` 进程常驻持有引脚，只有状态变化时才重启 —— 干净、稳定、不受内核干扰。

### 改造 2：引脚从设备树自动读

不再写死引脚号，而是启动时从设备树读：

```
/sys/firmware/devicetree/base/gpio-fan/gpios
```

兜底值 45。这样以后厂商再改 DTB 引脚，软件也不用动。

> 这个坑是真实存在的：厂商在 fnOS 1.2.0701 里把风扇 GPIO 从 **46 改成了 45**，写死引脚的脚本更新后全部失效。

### 改造 3：接管所有抢控制权的服务

安装后自动停用并禁用：`fanctl.service`、`pwm-fancontrol.service`、`fan-fullspeed.service`，并清理残留进程。保证只有本应用在控制风扇。

### 改造 4：卸载能干净还原

卸载时新增 `restore` 流程：结束 `gpioset` → 重新 `modprobe gpio_fan` → 恢复厂商的 60℃ 内核温控 → 重启 `pwm-fancontrol.service`。

**装完不满意，卸掉就回到系统原样，不留尾巴。**

## 四、顺手修掉的几个 BUG

1. **`oesp-fanctl status` 的「风扇状态」永远显示"关闭"**  
   原因是它只读守护进程的内存变量，单独执行命令时变量是空的。已改为回退读状态文件，再加 GPIO 实读兜底。
2. **`服务状态: 未安装或未运行` 是误导**  
   本应用由应用中心托管，根本没有独立的 `oesp-fanctl.service`。已改为显示「守护进程: 运行中 / 未运行」。
3. **风扇还没到关闭温度就提前停了**（原版遗留，最容易被忽略的一个）  
   原版把温度的小数截断掉再比较：`35.9℃` 被当成 `35℃`，于是「≤ 35℃ 就关风扇」在 **35.9℃ 就成立了**，实际停止点变成 36.0℃。  
   翻了一下设备日志，**466 次停止事件里有 455 次（97.6%）都发生在 35.0℃ 以上**——这就是「温度明明没到，风扇却停了」的真凶。已改为用毫摄氏度原始值精确比较。
4. **在 SSH 里敲 `oesp-fanctl set` 报「配置文件不存在」**  
   应用中心启动守护进程时会注入配置路径的环境变量，但你直接在终端执行命令时没有这些变量，路径就回落到了不存在的 `/etc/oesp-fanctl.conf`。已加上按实际安装位置自动发现。
5. **过热保护退出的一瞬间风扇会闪停一个周期**  
   过热强制开启只置了「紧急」标志，CPU 温控的防抖计数没攒够，紧急标志一退风扇就掉回关闭。已改为进入紧急保护时同步置位温控路径。

## 五、这软件能干什么

- 🔀 **三种运行模式（本次新增）**
  - **自动温控**（默认）：按 CPU / 硬盘温度自动启停
  - **常开**：风扇一直运行，完全不看温度 —— 夏天、硬盘多、或者你就想让它一直转
  - **常关**：风扇一直停止 —— 晚上嫌吵就切过去

  网页里点一下，或者敲一行命令，2 秒内生效：

  ```bash
  oesp-fanctl mode on      # 常开，风扇一直转
  oesp-fanctl mode auto    # 回到自动温控
  oesp-fanctl mode off     # 常关，风扇一直停
  ```

- 🌡️ **CPU 智能温控**：高于设定温度开风扇，低于设定温度关风扇，带迟滞防抖 + 最短运行时间保护，不频繁启停
- 💨 **硬盘定时通风**：任一硬盘超温就开启风扇，运行设定时长后自动停，停机间歇后再测温，循环到降温为止
- 🛡️ **紧急兜底**：CPU ≥ 70℃ 或硬盘 ≥ 55℃ 强制开启风扇
- 📊 **实时监控**：CPU / GPU / 三个盘位硬盘温度一屏看完，12 小时历史曲线
- ⚙️ **在线调参**：网页里直接改温度阈值、切运行模式，不用碰命令行

> ⚠️ 需要说明的是：OESP 内置风扇是 **GPIO 二态开关风扇，只支持「开 / 关」，不支持调速和档位**。这是硬件限制，任何软件都改不了。
>
> ⚠️ 另外提醒一句：**「常关」模式是强制覆盖，连过热紧急保护也会一起忽略**。临时静音可以，别长期挂着。

## 六、OESP 上怎么用

**第 1 步：确认环境**

- 机器：OES Plus（Amlogic S922X）
- 系统：飞牛 fnOS（ARM 版）

**第 2 步：安装**

应用中心 → 手动安装 → 选择 `oesp-fanctl_1.13_arm.fpk`

或者命令行：

```bash
appcenter-cli install-fpk /path/to/oesp-fanctl_1.13_arm.fpk
```

**第 3 步：什么都不用配**

安装完成后，应用会自动：

- 卸载内核 `gpio_fan` 驱动
- 从设备树读引脚号
- 停掉冲突服务
- 启动温控守护进程

**风扇即刻按温度自动启停。**

**第 4 步：看状态 / 调参数**

- 网页：浏览器访问 `http://<你的NAS地址>/app/oesp-fanctl`
- 命令行：`oesp-fanctl status`

默认阈值 **38℃ 开 / 35℃ 关**，可以在网页里随时改。

**想让风扇一直转？** 网页顶部的「风扇运行模式」点一下「常开 · 一直运行」，保存即可；或者命令行：

```bash
oesp-fanctl mode on      # 常开
oesp-fanctl mode auto    # 切回自动温控
```

> 小提示：如果你希望风扇更安静，可以把阈值调高（比如 45/38，或者厂商原设计的 60/55）。

**第 5 步：实时看温度**

```bash
fanlog          # 实时刷新温度、GPU、硬盘、风扇状态
```

**第 6 步：不想要了**

应用中心卸载即可，会自动恢复系统原本的风扇控制方式。

这个版本不是简单改几个参数，而是**换掉了整个控制通路**。
